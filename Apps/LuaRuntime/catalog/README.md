# SDK catalog

This directory is generated by `tools/sdk-catalog/catalog.py`. The curated,
human-maintained checklist is [`../CATALOG.md`](../CATALOG.md); these files are
the objective inventory behind it.

| File | Purpose |
|---|---|
| `sdk-coverage.md` | Summary, raw calls, unbound areas and declared candidates |
| `sdk-symbols.csv` | Full per-symbol inventory (module, status, header, notes) |
| `sdk-coverage.json` | Same data for tooling / future CI diffs |

## Sources

The SDK is an exported artifact. The firmware repository is the source of truth
for what a side-loaded app may resolve, so the generator prefers the firmware's
export tables:

- `TactilityKernel/source/symbols.c`
- `Modules/<module>/source/symbols.c`
- `Modules/<module>/source/module.cpp` (the `ModuleSymbol` table)

When a module has no export table in the firmware tree, the generator falls back
to the public SDK headers and marks those symbols **declared** rather than
**unbound**. Treat declared entries as candidates: confirm the export before
binding them.

The LVGL wrapper module re-exports the LVGL core, so its header lookup also
searches the SDK's `Libraries/lvgl/include/include/lvgl` tree.

## Status meanings

| Status | Meaning |
|---|---|
| `generated` | Declared as `c = "..."` in `bindings/*.toml` |
| `bound` | Referenced by a hand-written Lua binding in `lua_runtime/.../lua` or `lua_runner/.../luavgl` |
| `raw-only` | Exported and only reached through `tactility.raw.call()` |
| `raw-missing` | Used by a script through `raw.call`, but absent from the SDK |
| `unbound` | Exported/declared but not reachable from Lua yet |
| `declared` | Public header function in a module without an export table |

`bound` means the symbol is referenced by the binding code, not that every code
path has a test. The curated checklist carries the test/demo column.

## Regenerate

From the app directory (`Apps/LuaRuntime`):

```powershell
py tools\sdk-catalog\catalog.py
```

Options:

```text
--sdk PATH        TactilitySDK directory (default: newest installed SDK)
--firmware PATH   Firmware source tree (default: ../../TactilityWork)
--app PATH        LuaRuntime app directory
--output PATH     Catalog directory (default: catalog)
--check           Verify generated IDL symbols exist; write nothing
```

`--check` is the CI-friendly mode:

```powershell
py tools\sdk-catalog\catalog.py --check
```

It exits non-zero when a `bindings/*.toml` `c = "..."` name is missing from the
SDK/firmware inventory. That catches an SDK bump that removed or renamed an
export before a package ships and fails at runtime.

## Adding a catalogued capability

1. Add the function to `bindings/<capability>.toml` (generated) or to the
   hand-written binding.
2. Add a row to [`../CATALOG.md`](../CATALOG.md) with the demo/test that proves it.
3. Rerun `catalog.py` and commit the regenerated files.

For a new module, add it to `MODULE_NAMES` / `MODULE_TITLES` in `catalog.py` so
its headers are indexed and it gets a summary row.

## What is intentionally not catalogued

- libc, lwIP, mbedTLS and ESP-IDF internals.
- LVGL internals that a script should not call directly; the `lvgl-module`
  summary still exposes how much of the exported LVGL surface is reachable.
- In-memory firmware apps and app-hub content.
